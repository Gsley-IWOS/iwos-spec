# Documentation Standard

**Authority:** IWOS Engineering Constitution

**Last Updated:** 2026-07-31

## Purpose

This standard defines how IWOS documentation is authored, structured, reviewed, versioned and maintained so that system intent, decisions and execution knowledge remain clear, durable and auditable.

## Scope

This standard applies to all Markdown, YAML and specification documents in the IWOS specification repository and to documentation produced by IWOS implementation repositories when they reference constitutional or architectural behavior.

## Requirements

1. Every durable document must state its title, purpose, authority, version, status, parent document and ratification state.
2. Documents must use precise engineering language and avoid marketing claims, ambiguous phrasing and unstated assumptions.
3. Normative requirements must use consistent requirement language: **must**, **must not**, **should**, **should not** and **may**.
4. Documentation must distinguish ratified decisions from proposals, examples and explanatory notes.
5. Changes to governed documents must include a reviewable rationale and must preserve historical traceability.
6. Examples must be executable or explicitly marked as illustrative.
7. Documentation must not duplicate canonical definitions unless the duplication is clearly identified as a summary.

## Structure

Documentation should use the following order unless a more specific template applies:

1. Metadata
2. Purpose
3. Scope
4. Authority
5. Definitions
6. Requirements
7. Review criteria
8. Ratification

## Review Criteria

A documentation change is acceptable only when it is accurate, internally consistent, linked to the correct authority, free of placeholder language and understandable by a new contributor after reading the mandatory onboarding documents.

## Ratification

This standard is ratified for IWOS specification work and remains effective until superseded by a later ratified version.
