## Purpose

The Testing Standard requires structural, schema, consistency and example checks on every change, and the Architecture Baseline requires machine-readable engineering state and continuously updated engineering memory. Until now these requirements were met by hand, if at all. This package authorises the machine-readable contracts, the examples that exercise them, the validator that enforces them, the continuous-integration workflow that runs it, and the engineering memory records that the AI Agent Contract requires.

This package was drafted by an AI agent to give the build-out traceability. Its scope is a proposal until a Maintainer approves it.

## Objective

Every requirement of the Testing Standard, the integrity of every protected document, and the structure of every engineering memory record are verified automatically on every change.

## Scope

- `schemas/`: index, JSON Schema (draft 2020-12) for every governed YAML artefact, and the bindings file.
- `examples/`: index and at least one valid and one invalid example per schema.
- `tools/validate/`: the validator, its configuration, its unit tests and its README.
- `Makefile` at the root.
- `.github/`: pull request template, issue forms, continuous-integration workflow.
- `.ai/CONSTITUTION_LOCK.yaml`, generated by the validator. The other engineering memory records are EWP-0001 outputs and are updated by every package.
- `CHANGELOG.md`.

## Non-Scope

- Any change to `engineering-charter/` or `standards/`.
- Any IWOS implementation code. The validator validates this repository and nothing else.
- Specifications of components or engines.

## Inputs

- `standards/testing-standard.md`, `standards/engineering-standard.md`, `standards/security-standard.md`, `standards/repository-standard.md`.
- `engineering-charter/02_ARCHITECTURE_BASELINE.md` (State Model, Engineering Memory).

## Outputs

| Output | Path | Acceptance |
| --- | --- | --- |
| Schemas index | `schemas/README.md` | Lists every schema, its ID, version and the artefacts it binds. |
| Schemas | `schemas/*.schema.json` | Valid JSON Schema draft 2020-12; each carries `x-iwos-document` metadata. |
| Bindings | `schemas/bindings.yaml` | Maps every governed YAML artefact and every example directory to a schema; validates against `bindings.schema.json`. |
| Examples | `examples/<schema>/valid/*.yaml`, `examples/<schema>/invalid/*.yaml` | Every valid example validates; every invalid example breaks one rule, declares the expected error and is rejected with it. |
| Validator | `tools/validate/validate.py`, `tools/validate/config.yaml` | Implements structural, schema, consistency, example and integrity checks; exit code non-zero on any failure; exemptions carry reasons. |
| Validator tests | `tools/validate/test_validate.py` | Deterministic unit tests runnable with the standard library test runner. |
| Validator README | `tools/validate/README.md` | Documents every check, every configuration key and every exit code. |
| Makefile | `Makefile` | `validate`, `test`, `lock` and `install-deps` targets. |
| Continuous integration | `.github/workflows/validate.yml` | Runs validator and tests on pull requests and pushes to `main` with read-only permissions. |
| Pull request template | `.github/pull_request_template.md` | Contains the seven mandatory handoff sections in order. |
| Issue forms | `.github/ISSUE_TEMPLATE/*.yml` | Work package, RFC and defect forms; blank issues disabled. |
| Integrity lock | `.ai/CONSTITUTION_LOCK.yaml` | Generated by `make lock`; matches every protected document; validates against its schema. |
| Change log | `CHANGELOG.md` | Records every artefact added or changed by EWP-0001, EWP-0002 and EWP-0003. |

## Validation Criteria

- `make validate` passes.
- `make test` passes.
- Deliberately corrupting a protected document causes `make validate` to fail on the integrity check.
- Deliberately introducing a drafting marker, a broken link or a duplicate Document ID causes `make validate` to fail.
- The continuous-integration workflow runs the same commands as the Makefile.

## Completion Evidence

- Pull request with Summary, Files Changed, Decisions, Validation, Risks, Outstanding Work and Recommended Next Task.
- Validator output quoted in the pull request.
- `CHANGELOG.md` entry; `.ai/` records updated and the lock regenerated.

## Ratification

This package is approved by a Maintainer on merge to `main` with status `Approved`, or by a later change that sets its status to `Approved`. Work performed before approval is a proposal.
