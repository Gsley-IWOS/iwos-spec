**Last Updated:** 2026-11-14

## Purpose

A review of the toolchain on 2026-11-14 found that a single change could unprotect a file and rewrite it, that the security policy asked for vulnerabilities to be reported in public, that the gate kept no memory of what it had judged, and that a security finding led to no record and no procedure. The repository owner directed that every correction and recommendation from that review be implemented. This package authorises that work. It was drafted by an AI agent at that direction.

## Objective

The gate cannot be switched off by the change it judges; a vulnerability can be reported privately; a governed repository can learn from its own gate history, record exceptions and work a security incident to a close; and the decision on the toolchain's home is recorded.

## Scope

- `tools/iwos/`: base-constitution evaluation, control files, rule identifiers, waivers, event records, lessons, anonymous statistics, the incident ledger, SARIF output, the three new authority-interface tools, tests and README. Package version 0.2.0.
- `action.yml`: event record and SARIF outputs.
- `adr/ADR-0006`, `adr/ADR-0007`, `adr/ADR-0008`; `adr/ADR-0004` marked superseded.
- `architecture/engineering-governance/SPEC-ENGGOV-001.md`: Draft revision carrying the three decisions.
- `SECURITY.md`: private vulnerability reporting and the handling procedure.
- `AGENTS.md` generated block, `README.md`, registers, engineering memory and change log.

## Non-Scope

- Any change to a protected document, to `iwos.yaml` or to `tools/validate/config.yaml`.
- Creating the dedicated repository, moving the toolchain into it and tagging a release, which wait on the owner creating the repository (ADR-0006).
- Enabling private vulnerability reporting, branch protection and code scanning, which are settings on the hosting platform.
- Any transmission of data by the toolchain.
- A new document identifier family; the Naming Standard is not amended.

## Inputs

- `tools/iwos/` as merged under EWP-0005.

## Outputs

| Output | Path | Acceptance |
| --- | --- | --- |
| Base-constitution gate | `tools/iwos/src/iwos/gate.py`, `config.py` | The reproduced bypass fails the gate; a control-file change without a proposal citation fails; adoption is judged against the proposed constitution and reported as such; a head constitution that does not parse cannot disable the gate. |
| Rule catalogue and waivers | `tools/iwos/src/iwos/rules.py`, `gate.py` | Findings carry identifiers; a recorded waiver downgrades only a waivable rule on the paths it names until it expires; a waiver added in the same change does not apply. |
| Learning loop | `tools/iwos/src/iwos/events.py` | Event records hold no personal data and no free text; lessons never repeat text planted in the log. |
| Incident ledger | `tools/iwos/src/iwos/incidents.py` | Incidents are numbered, move forward only and keep a history; text matching a credential pattern is refused and nothing is written. |
| SARIF output | `tools/iwos/src/iwos/sarif.py` | Gate and validation findings are written as SARIF 2.1.0; a matched credential never appears in the file. |
| Decision records | `adr/ADR-0006`, `ADR-0007`, `ADR-0008` | Each records context, options, decision and consequences, including what the decision does not solve. |
| Security policy | `SECURITY.md` | Vulnerabilities are reported privately; the handling steps end in a published advisory. |
