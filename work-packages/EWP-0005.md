## Purpose

EWP-0004 built the reference toolchain. Before it is announced, a stranger must be able to install it, see evidence that it works on a real incident, trust what its report says about agents, and find the repository itself protected by the rules it sells. This package authorises that readiness work. It was drafted by an AI agent at the repository owner's instruction to start the next step; its scope is a proposal until a Maintainer approves it.

## Objective

A first-time visitor can read one true case study, install the toolchain with one command, and see the repository pass its own composite action on every pull request.

## Scope

- `tools/iwos/`: gate improvements found by replaying the repository's first agent pull request; tests; README; the case study.
- `adr/ADR-0005-agent-attribution-by-disclosure.md` and the matching clarification of the Draft specification.
- `.github/CODEOWNERS`; `.github/workflows/validate.yml` (run the composite action from the working tree); `action.yml` (pass pull request labels).
- `.mcp.json`: register the authority interface for agents working in this repository.
- `README.md`, registers, engineering memory and change log.

## Non-Scope

- Any change to a protected document.
- The product's final name, the release tag and the public announcement, which are the repository owner's acts.
- Branch protection settings, which are configured on the hosting platform and not in repository content.
- Publication to a package index.

## Inputs
