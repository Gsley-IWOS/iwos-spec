# RFC-0001: Establish the Request for Comments Process

**Status:** Accepted  
**Date:** 2026-07-31  
**Decision Owner:** IWOS Governance Authority  
**Applies To:** IWOS Specification Repository

---

## Purpose

Requests for Comments (RFCs) provide a lightweight mechanism for gathering structured feedback before a proposal becomes an AIP, ADR, standard, or implementation work package.

RFCs are intended for exploration, alignment, and discovery. They are not binding unless converted into an accepted authoritative artifact.

## When to Use an RFC

Use an RFC when the repository needs to collect input on:

- an emerging architecture concept;
- a potential standard or convention;
- an unclear governance issue;
- implementation approaches with broad impact;
- terminology or model changes that require shared understanding.

## RFC Requirements

Each RFC must include:

- the question or proposal under discussion;
- background and constraints;
- known options or open questions;
- requested feedback;
- review period or closing condition;
- final disposition.

## Lifecycle

RFCs move through the following states:

1. **Open** — feedback is being collected.
2. **Closed** — discussion has ended with a recorded disposition.
3. **Converted** — outcome was promoted into an AIP, ADR, standard, or work package.
4. **Withdrawn** — author or maintainers chose not to proceed.

## Non-Binding Nature

An RFC does not change architecture, governance, standards, schemas, or repository policy by itself. Any binding change must be captured in the appropriate authoritative artifact.
