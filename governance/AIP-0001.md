# AIP-0001: Establish the Architecture Improvement Proposal Process

**Status:** Accepted  
**Date:** 2026-07-31  
**Decision Owner:** IWOS Governance Authority  
**Applies To:** IWOS Specification Repository

---

## Purpose

Architecture Improvement Proposals (AIPs) provide the formal path for proposing meaningful changes to IWOS architecture, governance, standards, or specification behavior before those changes become binding.

The AIP process exists to ensure that major changes are intentional, reviewed, traceable, and aligned with the IWOS Founding Charter.

## Scope

An AIP is required when a proposal would materially affect:

- system architecture;
- governance rules;
- specification semantics;
- interoperability contracts;
- security, compliance, or audit behavior;
- repository authority structure;
- long-term implementation direction.

Minor editorial changes, typo fixes, and non-semantic clarifications do not require an AIP unless maintainers request one.

## Required Sections

Each AIP must include:

1. **Summary** — a concise statement of the proposed change.
2. **Motivation** — the problem or opportunity that justifies the proposal.
3. **Specification** — the proposed normative change.
4. **Impact** — affected documents, systems, stakeholders, and workflows.
5. **Compatibility** — migration requirements and backward-compatibility analysis.
6. **Alternatives** — meaningful options considered and rejected.
7. **Governance Outcome** — accepted, rejected, deferred, or withdrawn.

## Lifecycle

AIPs move through the following states:

1. **Draft** — proposal is being developed.
2. **Review** — proposal is ready for structured evaluation.
3. **Accepted** — proposal is approved and may be implemented.
4. **Rejected** — proposal will not proceed.
5. **Deferred** — proposal is valid but postponed.
6. **Superseded** — proposal has been replaced by a later AIP.

## Authority

Accepted AIPs may authorize new ADRs, standards, schema changes, or governance updates. The accepted AIP records the intent and approval; the corresponding implementation artifacts record the resulting authoritative detail.
